## 1. Что за граф

Логика: событие инициализации биндит мультикаст-делегат `Actor.OnActorBeginOverlap` на свой
Custom Event-хендлер; после бинда — `Sequence`, ветка A печатает отчёт, ветка B делает `Delay`,
после задержки exec переходит **на второй уровень**, где идёт `Branch` с условием из переменной
(нода данных — подряд под уровнем), `then` остаётся на уровне, `else` уходит на **третий уровень**.

Тестируемые шаблоны расстановки:

1. **Делегат** — хендлер (`event-for`) стоит **левее и ниже** ноды `Bind Event`, провод в `Delegate` идёт
   снизу-слева и не пересекает exec-цепочку (`@row=1 @col=-1` у узла 6).
2. **Последовательность** — каждый следующий узел ряда правее предыдущего (1 → 2 → 3); ветки ряда
   при этом расходятся по уровням: `4` остаётся в ряду 0, `5` уходит в полууреаь `0.5`.
3. **Развилка** — `Sequence` (два exec-выхода, оба использованы) и `Branch` (`then` + `else`).
   Дети узла с несколькими использованными exec-выходами образуют **столбец**: общий `X` = правый
   край родителя + зазор, по одному ряду на выход (`4` в ряду 0 и `5` в ряду 0.5 стоят на X=883).
4. **Несоосный exec-провод = стадиум из 4 knot-переносов с парным выравниванием по Y**
   (вердикт 2026-09-28: «первые два и последние два выровнены по Y между собой»):
   выход→K1 соосно X (нулевой), K1→K2 — горизонталь ПО СТРОКЕ ПИНА-ВЫХОДА, K2→K3 — вертикаль
   в свободной колонке, K3→K4 — горизонталь ПО СТРОКЕ ПИНА-ВХОДА, K4→вход соосно X (нулевой).
   Так идут и переносы между уровнями (`3.then_1 → 5`, `5.then → 7` назад-влево, `8.else → 11`),
   и короткое расхождение строк пинов внутри одного ряда (`1.then → 2`, `3.then_0 → 4`,
   `6.then → 12`, `7.then → 8`, `8.then → 10` — излом 16—32px). Провод, у которого пины на одной
   линии, остаётся прямой. Отдельная Y-линия коридора четвёрке не нужна: между уровнями проходит
   вертикаль, а не горизонталь.
5. **Нода данных под уровнем** — `Get bDebug` (строка `2.5`) питает `Branch.Condition`.

Номера узлов = номера в спеке, ими ссылаются `link`.

## 3. Критерии приёмки ступени 1 (генератор нод)

Генератор отвечает **только** за корректность нод: он не двигает и не соединяет ноды, а
закладывает расположение и соединения для расстановщика. Прогон
`node tools/gen-three-stage-test.mjs --stage 1` обязан выдать файл, в котором:

- [ ] 12 блоков `Begin Object` — ни больше, ни меньше;
- [ ] **все `NodePosX=0` и `NodePosY=0`** — генератор не расставляет (после вставки ноды лягут
  в одну точку у курсора, это и есть признак чисто-генераторного вывода);
- [ ] **ни одного `LinkedTo=(…)`** — генератор не соединяет; провода прокладывает ступень 2;
- [ ] нет `K2Node_Knot` (ступень 2) и `EdGraphNode_Comment` (украшательство);
- [ ] пины каждой ноды — из реестра/copy-back формы, имена и типы точные, у каждого пина свой
  `PinId` (32 HEX, уникален в ноде) — иначе ступени 2 не за что будет зацепить провод;
- [ ] `node src/validate.js` — 0 ошибок; round-trip `verifyStage1()` — 0 расхождений
  (текст ↔ модель: ноды, пины, отсутствие координат и связей);
- [ ] 0 предупреждений спеки (незаявленных exec-веток, пустых входов, коллизий ячеек).

Заложенные намерения (их в коде нет, они в спеке и в отчёте `--report`): 5 уровней
(`0, 1, 2, 2.5, 3`), 11 соединений, 12 узлов с трассировочными именами `…_1001…1012`
(`set nameBase 1000` = номер узла в спеке + 1000).

### Ступень 2 — расстановщик

| Правило | Реализация |
|---|---|
| материализация проводов | `applyConnections(nodes, connections)` — взаимные `LinkedTo` по `PinId`, иначе по имени пина; генератор их не пишет |
| уровни по маркам | `arrangeRows(rows, { gap, rowGap })` кладёт ряд слева направо, следующий ряд — `низ предыдущего + rowGap`; границы рядов собираются в `levels` (`top/bottom/nodes`) и возвращаются вместе с результатом; дробный `@row=0.5` — отдельный уровень |
| когда кладутся knot'ы | `createExecReroutes`: на каждый exec-провод, где `pinCenterY(выхода) ≠ pinCenterY(входа)` **или** левый край цели левее правого края источника. Соосный провод, идущий вправо, остаётся прямым — узлов нет |
| маршрут | **стадиум из 4 knot'ов** (`transferRoute`) с ПАРНЫМ Y (`src/arranger.js`): K1 на пине-выходе источника, K2 на той же строке пина-выхода, K3 и K4 — на строке пина-входа (выход K4 сидит на пине входа). X-колонка вертикали = `X пина-входа − 2·ширины knot'а`. Каждый участок соосен по X или по Y |
| колонка вертикали | `transferColumnX(...)`: колонка выбирается так, чтобы оба knot-прямоугольника 16×16 не наезжали на ноды, вертикаль K2→K3 не перечёркивала ни один прямоугольник нод на своём диапазоне Y и knot'ы не слипались; knot-тест учитывает и источник, и цель; при конфликте колонка перебирается дальше (засевки: у пина-входа → у пина-выхода → левый и правый внешние края, шаг ±W) — ноды не двигаются. `execCorridorY`/`rerouteCorridorY` остались для совместимого маршрута «пара knot'ов» (2 knot'а) и ступени 3 |
| что создаёт knot'ы | только ступень 2: `K2Node_Knot` с `InputPin`/`OutputPin` и разорванной исходной связью; ступень 3 переносы не создаёт и не удаляет |

Сознательные отступления и ограничения (их печатает `--report`, раздел «решения декоратора»):

- `6.OutputDelegate → 2.Delegate` — узел с exec-пинами не двигается ради провода данных, иначе
  рушится шаблон «хендлер левее и ниже ноды бинда»;
- **стадиумы кладутся только на exec-провода.** Провод данных между уровнями (`6.OutputDelegate →
  2.Delegate`) остаётся диагональным: механика knot'ов для него не заведена — это следующий
  кандидат, если захотите полную ортогональность графа;
- **несоосность строк пинов внутри ряда больше не лечится сдвигом ноды** (правило «ряд плоский»),
  она гасится knot'ами. Из-за этого в щели между соседями ряда живут 4 узла, и нужная щель —
  `4 * KNOT_W = 64px`. Pass 1 берёт `max(clearance, 64)`, поэтому при `set clearance 48` ряд
  разошёлся бы на 64px (проверено), а критерий E ловит наложение knot'ов друг на друга, если
  геометрию всё-таки сжать: при `clearance < 64` в декораторе узлы легли бы квадрат в квадрат;
- столбец детей форка **внутри одного ряда** физически невозможен (высота ноды 134px против шага
  пинов 32px) — поэтому он и делается маркой уровня (`@row=0.5`), а не решением декоратора.
