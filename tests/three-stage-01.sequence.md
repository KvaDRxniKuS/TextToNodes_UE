# Трёхступенчатый тест 01 — делегат + Sequence + второй уровень

Эталонная последовательность нод для проверки конвейера **по одному инструменту на ступень**:

| Ступень | Инструмент | Вход | Выход (файл для копирования в UE) |
|---|---|---|---|
| 1 — генератор нод | `src/stage1.js` (`tools/gen-three-stage-test.mjs --stage 1`) | эта спека | `tests/three-stage-01.stage1-generator.txt` — только код нод |
| 2 — расстановщик | `src/arranger.js` (`--stage 2`) | код ступени 1 + заложенные марки и соединения | `tests/three-stage-01.stage2-arranger.txt` |
| 3 — декоратор | `src/decorator.js` (`--stage 3`) | код ступени 2 | `tests/three-stage-01.stage3-decorator.txt` |

Файлы `.stage*.txt` генерируются (не правятся руками): `node tools/gen-three-stage-test.mjs`.
Блок ```graph ниже — единственный источник истины по нодам/связям/маркам: его читает
`parseSpec()` из `src/stage1.js`.

## 1. Что за граф

Логика: событие инициализации биндит мультикаст-делегат `Actor.OnActorBeginOverlap` на свой
Custom Event-хендлер; после бинда — `Sequence`, ветка A печатает отчёт, ветка B делает `Delay`,
после задержки exec переходит **на второй уровень**, где идёт `Branch` с условием из переменной
(нода данных — подряд под уровнем), `then` остаётся на уровне, `else` уходит на **третий уровень**.

Тестируемые шаблоны расстановки:

1. **Делегат** — хендлер (`event-for`) стоит **левее и ниже** ноды `Bind Event`, провод в `Delegate` идёт
   снизу-слева и не пересекает exec-цепочку (`@row=1 @col=-1` у узла 6).
2. **Последовательность** — каждый следующий узел ряда правее предыдущего (1 → 2 → 3, дальше ветки 4 и 5).
3. **Развилка** — `Sequence` (два exec-выхода, оба использованы) и `Branch` (`then` + `else`).
4. **Перенос уровня** — `5.then → 7.execute` идёт назад-влево на другой уровень → **стадиум из
   4 knot-переносов** (выход→K1 соосно X, K1→K2 соосно Y, K2→K3 соосно X по коридору, K3→K4
   соосно Y, K4→вход соосно X); так же `8.else → 11.execute`.
5. **Нода данных под уровнем** — `Get bDebug` (строка `2.5`) питает `Branch.Condition`.

Номера узлов = номера в спеке, ими ссылаются `link`.

| # | Нода | Класс UE | Пины в тесте | @row | @col |
|---|---|---|---|---|---|
| 1 | Custom Event `InitOverlapHook` | `K2Node_CustomEvent` | `OutputDelegate`, `then` | 0 | 0 |
| 2 | Bind Event to `OnActorBeginOverlap` | `K2Node_AddDelegate` | `execute`, `then`, `self`, `Delegate` | 0 | 1 |
| 3 | Sequence | `K2Node_ExecutionSequence` | `execute`, `then_0`, `then_1` | 0 | 2 |
| 4 | Print String `Bound` | `K2Node_CallFunction` | `execute`, `then`, `InString`… | 0 | 3 |
| 5 | Delay `0.2` | `K2Node_CallFunction` | `execute`, `then`, `Duration` | 0 | 4 |
| 6 | Custom Event `OnActorBeginOverlap` (подпись делегата) | `K2Node_CustomEvent` | `OutputDelegate`, `then`, `OverlappedActor`, `OtherActor` | 1 | −1 |
| 7 | Print String `AfterDelay` | `K2Node_CallFunction` | `execute`, `then`, `InString`… | 2 | 0 |
| 8 | Branch | `K2Node_IfThenElse` | `execute`, `Condition`, `then`, `else` | 2 | 1 |
| 9 | Get `bDebug` (своя переменная) | `K2Node_VariableGet` | `bDebug` | 2.5 | 0 |
| 10 | Print String `Yes` | `K2Node_CallFunction` | `execute`, `then`, `InString`… | 2 | 2 |
| 11 | Print String `No` | `K2Node_CallFunction` | `execute`, `then`, `InString`… | 3 | 0 |
| 12 | Print String `Overlap!` (логика хендлера) | `K2Node_CallFunction` | `execute`, `then`, `InString`… | 1 | 0 |

Соединения (ступень 1 их только **закладывает**; двусторонние `LinkedTo` в обеих нодах пишет
ступень 2 — `applyConnections`):

```text
1.then          → 2.execute           exec, ряд 0
2.then          → 3.execute           exec, ряд 0
3.then_0        → 4.execute           exec, ряд 0 (ветка A — отчёт)
3.then_1        → 5.execute           exec, ряд 0 (ветка B — задержка)
5.then          → 7.execute           exec, ПЕРЕНОС ряд 0 → ряд 2
6.OutputDelegate→ 2.Delegate          делегат (хендлер левее-ниже)
6.then          → 12.execute          exec, ряд 1 (цепочка хендлера)
7.then          → 8.execute           exec, ряд 2
9.bDebug        → 8.Condition         данные (нода данных под уровнем)
8.then          → 10.execute          exec, ряд 2
8.else          → 11.execute          exec, ПЕРЕНОС ряд 2 → ряд 3
```

## 2. Спека (читается инструментом)

Ступень 1 из марок берёт только **намерение**: `@row/@col` проверяются на корректность
(номер, уникальность ячейки, существование пинов под каждое `link`) и передаются ступени 2.
Сами координаты и провода генератор не пишет.

```graph
# ─── зазоры и сетка (расходуются ступенями 2 и 3, генератор их только хранит) ───
set grid 16            # клетка редактора UE
set nameBase 1000      # имя узла = <Класс>_(1000 + номер узла) — «узел 7» видно в тексте
set gap 160            # ступень 2: горизонтальный зазор расстановщика
set rowGap 160         # ступень 2: зазор между уровнями
set clearance 80       # ступень 3: зазор декоратора = 5 шагов сетки (5 * grid)

# ─── уровень 0: событие → бинд делегата → Sequence → ветки ───
1 event InitOverlapHook                                         @row=0 @col=0 @role=event
2 bind Actor.OnActorBeginOverlap                                @row=0 @col=1 @role=delegate-binder

# ─── уровень 1: хендлер делегата (левее и ниже ноды бинда) и его цепочка ───

8 fn Branch                                                        @row=2 @col=1 @role=branch
10 fn PrintString InString=Yes                                     @row=2 @col=2

# ─── связи пинов ───
link 1.then 2.execute

link 9.bDebug 8.Condition
```

## 3. Критерии приёмки ступени 1 (генератор нод)

Генератор отвечает **только** за корректность нод: он не двигает и не соединяет ноды, а
закладывает расположение и соединения для расстановщика. Прогон
`node tools/gen-three-stage-test.mjs --stage 1` обязан выдать файл, в котором:

- [ ] 12 блоков `Begin Object` — ни больше, ни меньше;
- [ ] **все `NodePosX=0` и `NodePosY=0`** — генератор не расставляет (после вставки ноды лягут
  в одну точку у курсора, это и есть признак чисто-генераторного вывода);
- [ ] **ни одного `LinkedTo=(…)`** — генератор не соединяет; провода прокладывает ступень 2;
- [ ] нет `K2Node_Knot` (ступень 2) и `EdGraphNode_Comment` (украшательство);
- [ ] пины каждой ноды — из реестра/copy-back формы, имена и типы точные, у каждого пина свой
  `PinId` (32 HEX, уникален в ноде) — иначе ступени 2 не за что будет зацепить провод;
- [ ] `node src/validate.js` — 0 ошибок; round-trip `verifyStage1()` — 0 расхождений
  (текст ↔ модель: ноды, пины, отсутствие координат и связей);
- [ ] 0 предупреждений спеки (незаявленных exec-веток, пустых входов, коллизий ячеек).

Заложенные намерения (их в коде нет, они в спеке и в отчёте `--report`): 5 уровней
(`0, 1, 2, 2.5, 3`), 11 соединений, 12 узлов с трассировочными именами `…_1001…1012`
(`set nameBase 1000` = номер узла в спеке + 1000).

## 4. Правила ступеней 2 и 3 (по вердиктам пользователя)

Ступень 1 принята, ступень 2 принята после правки коридора, ступень 3 переписана. Ниже — что
должно быть, как это реализовано и какие отступления сознательные (координаты из
`node tools/gen-three-stage-test.mjs --report`).

### Ступень 2 — расстановщик

| Правило | Реализация |
|---|---|
| материализация проводов | `applyConnections(nodes, connections)` — взаимные `LinkedTo` по `PinId`, иначе по имени пина; генератор их не пишет |
| уровни по маркам | `arrangeRows(rows, { gap, rowGap })` кладёт ряд слева направо, следующий ряд — `низ предыдущего + rowGap`; границы рядов собираются в `levels` (`top/bottom/nodes`) и возвращаются вместе с результатом |
| перенос между уровнями | **стадиум из 4 knot'ов** (`transferRoute`): K1 на пине-выходе источника, K2 под ним (общий X + ширина knot'а), K3 на коридорном Y у цели, K4 на пине-входе. Средние knot'ы имеют **один Y** — только у обратного (back) переноса он и нужен, чтобы горизонтальный участок шёл поперёк уровней и никого не резал |
| коридор | `rerouteCorridorY(source, target, levels)`: середина между самым низким низом уровней от источника до предшествующего цели и верхом целевого уровня (вверх — зеркально), привязка к сетке 16 |
| что создаёт knot'ы | только ступень 2: `K2Node_Knot` с `InputPin`/`OutputPin` и разорванной исходной связью; ступень 3 переносы не создаёт и не удаляет |

Открытые пункты (не блокируют): отдельного шаблона «делегат левее и ниже» нет — работает за счёт
марок `@col=-1`; дробный `@row=2.5` считается отдельным рядом и сдвигает следующий уровень вниз.

### Ступень 3 — декоратор

Критерии закреплены `node tools/check-decoration.mjs` (входит в `npm test`).

| Правило (формулировка пользователя) | Реализация |
|---|---|
| «Y exec-нод одного ряда должен быть идентичным» | pass 1: ряд — плоская лента; обход по exec-связям, `y` = Y ряда (никакой лесенки), `x` = правый край водителя + `clearance` |
| «если несколько exec-выходов — следующие ноды образуют столбец с числом рядов в число выходов» | дети узла с `>1` использованным exec-выходом получают общий `X = правый край родителя + clearance`; если ребёнок в другом уровне — его Y остаётся Y его уровня (столбец по X, ряд не перетекает) |
| «Y должен совпадать только у knot-нод back-переноса» | pass 4: `transferRoute` по пинам концов; совмещается Y только средних knot'ов (горизонталь коридора), Y нод при этом не «подтягивается» к пинам |
| «зазор 5 шагов сетки по X» | `clearance = 5 * grid = 80` (`set clearance 80`) |
| данные (`9.bDebug → 8.Condition`) | pass 2: двигаются только «чистые» ноды данных; в одном ряду — пин в пин + зазор, из другого ряда — строго под пин входа (`X` правого края = `X` пина-входа), провод вертикальный |
| «уровни должны сохраниться» | состав уровня, его верх (минимальный Y) и код нод не меняются; если выравнивание съело щель, ряд и всё под ним сдвигается вниз (`minLevelGap`), а не переставляется между уровнями |
| сетка 16 | `snap: false` — округление разбирает соосность пина и knot'а |

Сознательные отступления (их печатает `--report`, раздел «решения декоратора»):

- `6.OutputDelegate → 2.Delegate` — узел с exec-пинами не двигается ради провода данных, иначе
  рушится шаблон «хендлер левее и ниже ноды бинда»;

## 5. Прогон

```bash
node tools/gen-three-stage-test.mjs            # все три файла (перегенерация)
node tools/gen-three-stage-test.mjs --stage 1  # только генератор (читает спеку ниже)

```

GUID детерминированы (`seedGuids('three-stage-01')`), поэтому повторный прогон не создаёт
шума в diff и файлы сверяются побайтово. Для вставки в UE: `.stage1-generator.txt` целиком
(`Ctrl+V` в EventGraph), переменную `bDebug` нужно завести в BP (или заменить узел `#9`).
