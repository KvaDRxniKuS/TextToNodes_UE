# Образцы раскладки от пользователя (2026-09-30)

Сами дампы приватные и в репозиторий не кладутся. Здесь записаны только выводы.

## 1. LongitudinalVector&W: эталон, режим `column`
- Секции оформлены комментариями, в левом верхнем углу каждой стоит Sequence.
- Выходы then_i идут в столбец Set с шагом 96–128.
- Слева от каждого Set лежит своё дерево данных (Get → операторы).
- Последний then переходит в следующую секцию через пару knot'ов.

## 2. MoveVars: эталон, режим `chain`
- Set'ы стоят горизонтальным рядом (один Y, шаг около 240).
- Дерево данных каждого Set лежит в промежутке перед ним.
- На входе стоит Branch раннего выхода.
- Общий Get может питать нескольких соседних потребителей.

## 3. EventGraph BP_WheelActor: «частично, но грязно»
Что сделано хорошо (берём в правила):
- Главная exec-линия BeginPlay идёт горизонтальной цепочкой на одном Y (AddComponent → SetBoxExtent → SetHiddenInGame → SetCollision… → SetWorldLocation).
- **Ряд подписок:** AddDelegate ×3 стоят в одну линию, под каждым висит своё событие-обработчик, от него идёт свой короткий ряд (Event → Branch → Set → Set → SetTimer).
- Общая объектная ссылка (Get BP_Vehicle) подаётся нескольким потребителям по горизонтальной шине data-knot'ов над рядом.
- Геттеры дублируются у потребителей (Forward ×3, Steer ×2).

Что сделано грязно (запрещаем в расстановщике):
- Sequence.then_0 уходит вверх, вложенный Sequence тоже уходит вверх, Branch оказывается на 600px выше родителя. Правило: выходы Sequence раскладываются только вниз (then_0 на уровне Sequence, остальные ниже).
- Exec-провод Steering → SetRelativeRotation тянется на ~1900px поверх собственного дерева данных. Правило: если дерево шире лимита промежутка (около 480px), оно уходит под ряд, а не в промежуток; exec-провод держится коротким.
- Один выход Map_Find тянется к трём далёким потребителям, провода идут против потока. Правило: для чистого источника дальше 1 колонки — дубль или knot-шина.
- Разрыв около 1000px внутри цепочки (Set Chassis → AddComponent): промежуток занят чужим деревом.
- Вплотную стоящие ноды разных веток: Print(CastFailed) у Get Cabin в одной колонке.
- Висящая нода без exec (PrintText на 7152,0): её должен помечать линтер, а не расстановщик.
- Нет комментариев-секций.

## Реализовано (2026-09-30, после проверки тестером: блок C «в ряд» собран хорошо)

- `section-layout`: **шина** — в секции `layout:'chain'` поле `bus:'Имя'`, в выражениях `'$Имя'`.
  Один Get слева у Sequence, полоса knot'ов между рядом Set'ов и деревьями, knot на каждого потребителя
  (образец 3: шина BP_Vehicle). Демо: секция C, шина `Dt`.
- `section-layout`: **ряд подписок** — `layout:'bind'`, `binds:[{delegate, handler, steps}]`.
  Bind'ы в линию (then_0 Sequence), под каждым — событие с сигнатурой делегата и его короткий ряд Set'ов,
  деревья под рядом (образец 3: AddDelegate + обработчики). Демо: секция E.
- `src/layout-lint.js` — `lintLayout(nodes)`, только предупреждения, ничего не двигает:
  L1 exec-нода без входящего exec · L2 выход Sequence вверх · L3 провод данных > 1200px по X ·
  L4 exec-провод > 1600px по X (шина knot→knot не в счёт). Демо: 0 замечаний.
- Не сделано: правило «дерево шире ~480px — под ряд» как автоматика (в chain-режиме деревья уже под рядом),
  автодублирование геттеров (генератор и так ставит свой Get на каждое использование; шина — по явному `bus`).
